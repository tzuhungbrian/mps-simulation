# 3D 沙盒量測模型（MVP2：已知校正的理想掃描器）

本里程碑提供可移動三維物體的**正向模擬 → 三張強度影像 → 既有三步相移解碼 → 校正幾何三角測量**。它不是完整相機／投影機校正估計器，也不是 MicroPS 實作。內外參由合成場景直接指定；反算時使用這些已知參數，不會估計或讀取物體表面。

## 資料邊界

- `createWorld(config)` 建立顯示與 CPU 正向模型共用的三角網格定義。
- `captureWorld(config, width=96, height=72, onProgress?)` 將同一網格轉成世界座標 BVH（three-mesh-bvh），以相機像素中心射線取得最近表面，建立三張 `Float64Array` 強度影像，另輸出僅供評估的 `direct`、`indirect` 分量，以及互反射開啟時同雜訊、無間接光的 `directOnly` 對照影像。
- `reconstructCaptures({width,height,frames,clipped}, camera, projector)` **只能使用影像、裁切旗標與已知校正**，呼叫 `src/core/simulation.ts` 的真正 `decodeThreeStep`。不輸入網格、真實投影座標、真實深度、遮蔽遮罩、光傳輸分量、參考相位或條紋級次。
- `runWorldScan` 將正反向串接後，才以 `truthDepth` 評估誤差。其反算呼叫顯式建立四欄位物件，避免評估資料越界。互反射開啟時，另對 `directOnly` 跑同一反算，得到 `directRmseDepth` 作為反事實對照。
- 介面透過 `scan.worker.ts` 在 Web Worker 執行 `runWorldScan` 並回報進度；場景改動時終止舊 Worker，舊結果不會覆蓋新場景。
- `parseWorldConfig(unknown)` 驗證匯入值並回傳只含已知欄位的副本；不將字串轉成數字。`validateWorldConfig(config)` 對無效範圍拋出 `RangeError`。

## 場景與座標

世界座標為右手系，Y 向上，長度使用一致的場景單位。預設物體為中心 `(0,0.75,0)`、半徑 `0.65` 的球，三角網格為 24×16 分段。另提供 1.2×1.2×1.2 立方體、1.5×0.4×1.2、繞 Z 軸旋轉 −0.35 rad 的斜板，以及 1.6×0.8×1.2 的 V 型槽塊：槽沿 Z 軸、夾角 θ ∈ [30°,150°]，槽深 `min(0.6, 0.7/tan(θ/2))`、半開口 `槽深·tan(θ/2)`。地面為 Y=0 的 10×10 平面。所有幾何皆為雙面測試，射線測試與顯示使用相同幾何；光照使用世界座標的**三角形面法線**（由頂點繞序決定，封閉網格朝外）。

相機預設位置 `(0,3.5,0)`（物體正上方、朝正下方拍），投影機預設位置 `(2.5,0.75,0)`（與物體中心同高、在通過物體中心的 X 軸上，從側面水平照射）。兩者位置皆可調整，朝向則永遠對準**物體目前的中心** `(x,y,z)`；移動物體會同時改變已知外參。相機預設垂直視角 45°、96×72；投影機固定垂直視角 55°、160×120。反算不依賴簡化的視差公式。預設配置下 V 型槽內部低於槽緣的投影機高度，槽壁不會被照到；要觀察槽壁請把 Projector 抬高。

設定範圍：物體 X/Z ∈ [−2,2]、Y ∈ [0.65,2.5]；裝置 X ∈ [−5,5]、Y ∈ [0.3,6]、Z ∈ [−5,6]，且光心距物體中心至少 0.5；grooveAngle ∈ [30°,150°]，cameraFov ∈ [30°,75°]，seed 為 uint32 整數，noiseSigma ∈ [0,0.01]；物體／地面／晶片／引腳 albedo、specular ∈ [0,1]、roughness ∈ [0.05,1]；cameraWidth ∈ [64,384] 且為 4 的倍數（高度 = 3/4 寬度），pixelGrid ∈ {1,2,3}；interreflection 為布林，bounces ∈ {1,2,3}，giSamples ∈ [8,256] 整數；數值必須有限。形狀僅接受 `sphere`、`box`、`ramp`、`vgroove`、`pcb`。參數 JSON 為 schemaVersion 3；舊版檔案不再接受。

PCB（放大模型）：1.6×0.08×1.2 板子（物體材質），U1 QFP（四邊各 6 支鷗翼引腳）、U2 SOIC（兩邊各 5 支）、J1 2×4 排針（垂直針腳）、R1/C1/C2 被動元件（兩端金屬端子），共 48 支引腳；引腳寬 2.2 cm、厚 1.2 cm。每個頂點帶 `surface`（0 板、2 晶片、3 引腳）與 `pinId` 屬性，光傳輸依此選材質，評估依此分類。選 PCB 時套用 `PCB_SETUP`：板子 y=0.65、Camera (0,2.6,0) 俯拍、Projector (1.2,2.3,0)、256×192、2×2 面積積分、綠漆板材。

**像素面積積分**：pixelGrid = n 時，每個像素以 n×n 子射線（偏移 (j+0.5)/n − 0.5）平均直接光與間接光；間接光每個子射線用 round(giSamples / n²) 條路徑。真值深度、表面類別、引腳 ID 與 shadowMask 仍取像素中心射線。跨邊緣的混合像素會解出介於兩個表面之間的相位，這是低解析度下小細節重建失敗的主要原因。

## 針孔投影與像素中心

令位置為 C、目標為 T（物體中心），baseline 為 b = P_projector − C_camera。兩台裝置的影像水平軸都取 b 垂直於各自光軸的分量，因此投影條紋一定橫跨 baseline 變化、column 光平面不會包含 baseline（否則三角量測退化）：

```text
f = normalize(T − C)
r = normalize(b − (b·f) f)          // b ∥ f 時改用 f × Y；再退化則用 f × (−Z)
u = r × f
cx = (W − 1)/2, cy = (H − 1)/2
fy = H / (2 tan(fovY/2)), fx = fy
```

像素索引 `(x,y)` 本身就是像素中心；影像 Y 向下。射線方向為：

```text
d = normalize(f + ((x−cx)/fx) r − ((y−cy)/fy) u)
X(t) = C + t d
```

世界點 X 的投影為：

```text
Z = (X−C) · f
pixelU = cx + fx ((X−C)·r)/Z
pixelV = cy − fy ((X−C)·u)/Z
```

Z≤0 或非有限值均無有效投影。`makePinhole` 會拒絕重合的目標／位置；若視線與世界上方向平行（正上方或正下方），改用 `−Z` 作為參考方向求 right，影像上方因此朝向 `−Z`。投影機有效視錐邊界是 `−0.5 ≤ pixelU < W−0.5` 與 `−0.5 ≤ pixelV < H−0.5`，不是 `[0,W−1]`。

## 正向光照、遮蔽與三張拍攝

每個相機像素僅取最近交點，不做多重表面混合。將交點投影至投影機後檢查視錐，再從投影機向該交點射線測試。只有從投影機到該點之間（扣除容差 `1e−6 × max(1,距離)`）沒有任何交點時才視為可見；此寫法不受相鄰三角形共用邊上的浮點裂縫影響。因此會出現物體自遮蔽與投影機在地面上的陰影；相機端的遮蔽則由首次最近交點自然決定。

對可照明交點，令外向世界面法線為 n，朝投影機的單位方向為 l，朝相機為 v。投影機視為點光源、不含距離平方衰減：

```text
q = (projectorU + 0.5) / projectorWidth       // 0 ≤ q < 1
phi = 2π q − π
p_k = 0.4 + 0.36 cos(phi + delta_k)            // 投影圖案 ∈ [0.04, 0.76]
delta = [0, 2π/3, 4π/3]
f(l,v) = (1−s)·ρ/π + s·D(h)·G(l)G(v) / (4 (n·l)(n·v))   // Lambert + GGX
D(h) = α² / (π((n·h)²(α²−1)+1)²),  α = roughness²,  G = Smith GGX
direct_k = π · f(l,v) · (n·l) · p_k
I_k = clip(0.12 + direct_k + indirect_k + noise, 0, 1)
```

ρ 是漫射反射率、s 是鏡面權重（常數 Fresnel），物體與地面各自一組；預設物體 ρ=0.8、地面 ρ=0.5、s=0。介面提供無色近似的材質預設（`MATERIAL_PRESETS`：霧面白漆、石膏、灰色霧面地板、水泥、亮漆木頭、亮面塑膠、上釉陶瓷、黑色橡膠、拉絲金屬、拋光金屬、鏡面）；金屬類 ρ=0、s ≥ 0.85，只有鏡射方向附近的像素有條紋。純 Lambert 時 `I_k = 0.12 + ρ (n·l) p_k`。低粗糙度鏡面在鏡射方向會产生超過 1 的高光而被 clipping。

**互反射**（`interreflection=true`）以 Monte Carlo 路徑追蹤估計 `indirect_k`：每個像素從相機交點發出 `giSamples` 條路徑，每次反射依 Lambert/GGX 混合密度取樣方向、乘上 `f·cos/pdf`，在每個後續頂點做投影機 next-event estimation（含可見性射線），最多 `bounces` 次。同一路徑同時累加三個相移的 `p_k`，因此 Monte Carlo 雜訊在三張影像間完全相關，表現為系統性相位偏差而非獨立雜訊。亂數流由 `seed ^ 0x9e3779b9` 產生，與感測器雜訊分開，結果可重現。相機交點的直接光仍精確計算，不含取樣雜訊。

單週期條紋下，間接光來自投影機其他 column，其相位與本點不同，會把解出的相位拉向那些 column，造成系統性深度誤差（預設 V 型槽、一次反射約 0.1 m RMSE）。這正是高頻條紋（包括 Micro PS）要抑制的效應。

沒有相機交點、超出投影機視錐、被遮蔽、n·l≤0 或相機看到背面時，`direct_k=0`。互反射關閉且零雜訊時，背景、剪影外與陰影三張影像都為常數 0.12，不會補上真實深度；互反射開啟時，陰影區可能因間接光帶有調變而被解碼（等同實機的錯誤重建）。極斜的可見面也可能因 B≤0.01 被閾值排除。

`cameraHit` 僅表示相機看見表面。`shadowMask` 表示**相機有交點但投影機不能照明**，包含遮蔽、視錐外與背光；不是只計算幾何投影陰影。背景的 `shadowMask=0`、`truthDepth=NaN`。

可選雜訊對每個像素、每張曝光獨立加入 seed 可重現的 Box–Muller Gaussian 值，之後將強度裁切至 [0,1]。任一曝光達到或越過端點即設定該像素 `clipped=1`；裁切像素不解碼。預設 sigma=0。雜訊也加在背景／陰影上；非零 sigma 下，偶爾會讓無照明像素的雜訊調變超過閾值，成為假陽性，**不會使用真實遮罩偷偷移除**。

## 解碼與單週期的適用限制

解碼器對三張強度計算：

```text
N = √3 (I_2 − I_1)
D = 2 I_0 − I_1 − I_2
wrapped = wrap[-π,π)(atan2(N,D))
B_hat = hypot(N,D)/3
A_hat = (I_0 + I_1 + I_2)/3
```

僅接受有限、未裁切且 `B_hat > 0.01` 的相位。本模型在**整個投影機寬度只放一個完整週期**，且已知交點來自 q∈[0,1) 的視錐，因此可唯一轉回投影機欄座標：

```text
projectorU = projectorWidth (wrapped + π)/(2π) − 0.5
```

這不是一般高頻條紋的絕對相位展開。若改為多個週期，單靠三步相移無法確定條紋整數級次，必須另加 Gray code、多頻或其他真正的消歧資訊；不能以場景真值補級次。目前沒有列方向 spatial unwrap，也沒有參考相位錨定。

## 由投影機欄平面三角測量

投影機欄座標 U 對應通過投影機光心 P 的平面：

```text
n_plane = projector.right − ((U−projector.cx)/projector.fx) projector.forward
n_plane · (X−P) = 0
t = n_plane·(P−C) / (n_plane·d)
X = C + t d
```

近乎平行（相對閾值 1e−12）、非有限交點、相機或投影機後方的點都拒絕。重建另檢查投影機視錐，最後輸出 `depth=(X−C)·camera.forward` 與世界座標 XYZ；無效深度／XYZ 都為 NaN。`phase.valid` 是光度有效性，`reconstruction.valid` 還要求幾何有效，兩者不必相同。

## 評估與已知簡化

- `analyzeScan(scan, tolerance, pins?)`（`src/sandbox/analysis.ts`）產生點雲分析頁的全部數字：有號誤差 e = 重建 Z − 真值 Z 的 RMSE、MAE、平均偏差、|e| 中位數／P95／最大、容差內點數、對稱直方圖（範圍 max(容差, P95)，超出者併入兩端）、依表面統計，以及每個無效像素恰好一個失效原因（依序：無相機交點→背景、clipping、相位無效且 shadowMask→未照明、相位無效→調變過低、其餘→三角量測無效）。PCB 引腳：可見＝像素中心打到該引腳的像素；成功＝容差內像素 ≥ max(1, 可見/2)，部分＝至少一個，失敗＝可見但無，看不到＝可見為 0。此模組讀取真值，只用於評估。

- `truthDepth` 與重建深度都是**相機光軸 Z**，不是光心到表面的歐氏距離。
- RMSE 僅使用「重建有效且 truthDepth 有限」的樣本，另報 `evaluatedCount`；沒有可評估樣本時為 null。
- `validRatio = validCount / (width × height)`，分母是**所有相機像素**，不是相機命中數，也不是只算物體。
- `cameraHitCount` 是相機看見的像素數；`occludedCount` 為上述廣義 `shadowMask` 數量。地面也包含在所有影像、重建與統計內。
- 相機／投影機皆為理想針孔，無畸變、校正誤差、逆平方衰減、gamma、散焦、次表面散射或有限曝光。材質為無色、Fresnel 為常數；像素面積積分預設關閉（點取樣），開啟後為均勻子射線平均，不含鏡頭 PSF 或抗鋸齒濾波。互反射只在場景網格內傳遞，射出場景的路徑視為 0。
- CPU 正向影像與反算以 Float64 執行（BVH 頂點為 Float32 世界座標）；Three.js GPU 的投影 shader、色調映射、深度陰影貼圖與顯示取樣只用於互動視覺呈現，**不讀回 GPU 畫面當成量測輸入**。GPU 只套用漫射反射率，不顯示鏡面高光與互反射；GPU 平滑法線／陰影解析度等外觀細節不等同 CPU 面法線／精確射線測試。
- 預設 96×72 是為互動延遲而選的低解析度，不代表感測器精度。`captureWorld` 在 finally 釋放暫時網格與材質；外部顯示用 `createWorld` 的呼叫者需自行呼叫 `dispose()`。釋放的是建立時擁有的原始資源，不會誤釋放呼叫者替換的 shader 材質。
